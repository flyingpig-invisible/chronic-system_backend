## 五、已知遗留 / 坑点（重要）

1. **字符编码**：部分老文件含中文乱码（GBK 误读）。读文件时若终端显示乱码，用 `io.open(path, encoding="utf-8")` 或 PowerShell `[IO.File]::ReadAllText(path,[Text.Encoding]::UTF8)` 读取；**写文件务必用 UTF-8 无 BOM**，否则页面中文再次损坏。`list.vue`、`PatientSelect.vue` 已在本次修复为正常中文。
2. **逻辑删除**：全局配置了 `logic-delete-field: delFlag`，仅对含该字段的实体生效；`cd_health_score` 无此字段，删除即物理删除。若要改成逻辑删除，需先加列并改实体。
3. **风险等级仍可能被预警抬高**：`CdWarningServiceImpl.checkAndCreateWarning` 在命中预警时仍会「只升不降」地改 `cd_patient.risk_level`，与“以最新评分为准”存在潜在冲突。若要求完全统一，应改为触发预警后自动重算评分，或让档案接口只认评分记录（现已优先取评分记录，但患者在无新评分时仍可能显示被抬高值）。
4. **手动录入监测数据不触发预警**：后台 `CdMeasureServiceImpl.addMeasure` 不会调用预警校验，也不会更新风险等级；只有小程序上报路径 `MpMeasureServiceImpl` 会调用 `checkAndCreateWarning`。
5. **评分计算依赖权重与指标交集**：`calcScore` 只对「患者有最新监测值 且 该病种有权重配置」的指标加权；两者无交集时退化为等权。新增的自定义指标若不在 `RANGE` 参考区间内，风险度固定按 0.5 计算（见 `CdScoreServiceImpl.RANGE`）。
6. **档案页无评分时的回退**：没有 `cd_health_score` 记录的患者仍显示 `cd_patient` 中的旧值，历史脏数据不会自动纠正。
7. **未做构建验证**：本次会话所有改动均未编译/打包，`node --check` 仅校验过前端 `<script setup>` 语法（Vue 模板未静态校验）。第一次启动若报错，优先检查本次新增的模板插值和方法名拼写。

## 六、常用排查 SQL

```sql
-- 患者风险与最新评分对照
SELECT p.patient_id, p.name, p.risk_level AS patient_level, p.risk_score AS patient_score,
       s.total_score, s.risk_level AS score_level, s.calc_time
FROM cd_patient p
LEFT JOIN (SELECT h.* FROM cd_health_score h
           JOIN (SELECT patient_id, MAX(calc_time) mt FROM cd_health_score GROUP BY patient_id) t
             ON h.patient_id = t.patient_id AND h.calc_time = t.mt) s
       ON s.patient_id = p.patient_id
ORDER BY p.patient_id;

-- 某病种权重合计（应恒为 1）
SELECT disease_code, SUM(weight) FROM cd_score_weight GROUP BY disease_code;

-- 某患者监测数据最新值
SELECT indicator_code, value, unit, measure_time FROM cd_measure
WHERE patient_id = 6 ORDER BY measure_time DESC LIMIT 10;
```

### 1. 多病种综合评分（按病种等权，可手动调整）
- 病种来源改为 `cd_patient_disease`（不再取监测记录上的 `disease_code`）。
- 每个病种单独计算：该病种指标权重命中最近监测值的指标做加权；无交集时等权。
- 综合分 = Σ(病种分 × 病种占比)；等级仍按分数：`>=80 高危 / >=50 中危 / 其余低危`。
- 病种占比表：新建 `cd_disease_weight`（`disease_code/disease_name/weight`），默认四病种各 0.25。
  - 约定：**所有病种配置权重相等时视为“默认平分”**，按患者实际病种数取 1/n（两病即 50%/50%）。
  - 设为不等权重时，须合计为 1 且覆盖该患者全部病种，否则回退平分。
- 接口新增：`GET /chronic/score/weight/combined?diseaseCodes=1,2`、`POST /chronic/score/weight/combined/save`。
- 评分列表支持 `diseaseCode` 过滤（匹配明细 JSON 中的 `"diseaseCode":"x"`）。
- 页面：权重配置页新增病种按钮组与「病种间权重」弹窗；评分记录页新增病种列、明细按病种分块。
- SQL：`sql/migrate_disease_weight.sql`（可重复执行），`init_all.sql` 已含该表。

### 2. 手工录入即触发预警
- `CdMeasureServiceImpl.addMeasure` 保存后调用 `warningService.checkAndCreateWarning`，命中规则立即生成 `cd_warning` 并回写监测 `abnormal_flag=1`。
- 事务提交后（`afterCommit`）自动重算该患者评分并更新档案，保证能读到新数据。
- 小程序上报 `MpMeasureServiceImpl.submit` 同样在保存后重算评分。

### 3. 风险评分 = 指标加权分 + 预警加分
- `CdScoreServiceImpl.calcScore`：
  - 基础分：各病种加权分 × 病种占比（上限 100）。
  - 预警加分：逐指标取最近一次监测值套用 `cd_warning_rule`，命中**中危 +10、高危 +20**（低危不加分，多指标累加）。
  - 总分 = min(100, 基础分 + 加分)，等级仍按总分划分。
- 明细 JSON 增加保留键 `_summary`：`{ baseScore, warningBonus, warningHits[] }`；接口同时返回这三个字段。
- 评分明细弹窗展示“基础加权分 + 预警加分 = 最终分”及命中的规则清单。

### 4. 等级口径统一
- `checkAndCreateWarning` **不再**直接用预警级别抬高 `cd_patient.risk_level`（原“只升不降”逻辑已移除），等级以评分为准。
- 新增 `CdWarningService.matchRuleCode` 供评分复用；规则匹配只按 `indicator_code`，不校验患者病种。
- 档案详情在无评分记录时，用未处理/处理中预警的最高级别兜底；有评分记录时以评分为准。
