## 五、已知遗留 / 坑点（重要）

1. **后端未重启**："角色授权权限收回"（F 项）的代码改动需重启后端才生效。
2. **前端角色兜底隐患**：`frontend/src/store/user.js:41` 的 `roles.length ? roles : ['doctor']` 会把空角色伪装成 doctor，掩盖真实的权限缺失，建议改为不兜底、如实展示。
3. **孤儿账号无自动约束**：新建用户 / 改用户角色时没有强制至少绑定一个角色，导致 `doctor03` 这类账号出现。建议在用户保存逻辑中加校验。
4. **`removeRole` 非原子**：先删角色、再删 `sys_role_menu`，中途失败会留下孤儿关联（`@Transactional` 已加，但仍建议确认）。
5. **`RoleInitRunner.ensureBuiltInRoles()` 未加 try-catch**，失败会影响启动。
6. **前端侧边栏读的是 `router/index.js` 静态路由**，不读 `sys_menu` 表；改菜单不会自动改侧边栏。
7. **历史评分明细不会自动修复**：早前 `detail` 用 `putAll` 导致多病种互相覆盖，已改为按病种分组，但旧记录需重算。
8. **监测录入相关缺陷仍未修**：`LocalDateTime` 反序列化报 `Text '2026-11-19 19:52:02' could not be parsed at index 10`（缺全局 Jackson 格式配置）；录入表格未按患者病种动态生成指标行，且一次只能录一条（后端 `/chronic/measure/batch` 已存在但前端未使用）。

## 六、常用排查 SQL

```sql
-- 某用户绑定的角色
SELECT u.user_id, u.username, u.del_flag, GROUP_CONCAT(r.role_key) AS roles
FROM sys_user u
LEFT JOIN sys_user_role ur ON ur.user_id = u.user_id
LEFT JOIN sys_role r ON r.role_id = ur.role_id
GROUP BY u.user_id, u.username, u.del_flag;

-- 某角色拥有的全部权限点
SELECT r.role_key, GROUP_CONCAT(m.perms ORDER BY m.menu_id SEPARATOR ',') AS perms
FROM sys_role r
JOIN sys_role_menu rm ON rm.role_id = r.role_id
JOIN sys_menu m ON m.menu_id = rm.menu_id
WHERE r.role_key = 'doctor' AND m.status = '0' AND m.perms <> ''
GROUP BY r.role_key;

-- 查找"代码在用但菜单表缺失"的权限点：把控制器里的 hasPermi 值与下面的结果做差集
SELECT DISTINCT perms FROM sys_menu WHERE perms IS NOT NULL AND perms <> '';

-- 角色管理相关权限分布
SELECT r.role_key, m.menu_id, m.menu_name, m.perms
FROM sys_role r
JOIN sys_role_menu rm ON rm.role_id = r.role_id
JOIN sys_menu m ON m.menu_id = rm.menu_id AND m.perms LIKE 'system:role%'
ORDER BY r.role_key, m.menu_id;
```
