## 0. 先说清一件事：不是"预留接口"

"预留接口"这个说法是错的。前端自己拍字段、后端自己拍结构，等到联调那天两边一起推倒重来 —— 这是最常见的翻车方式。

正确做法是**契约先行**：

| 做法 | 结果 |
|---|---|
| 前端"预留"几个空函数，等后端给地址 | 字段名、结构、错误码全对不上，联调等于重写 |
| 先定这张契约表，两边各自照它开发 | 后端没上线时前端用 mock 顶着；后端上线只改一个 `BASE_URL` |

所以分工是：

1. **两边一起把第 3 节的接口表过一遍**（1 小时，逐行确认字段）——这一步做完，80% 的联调问题就消失了。
2. **前端**：把现在页面里直接 `require('utils/mock.js')` 的写法，改成统一走 `utils/api.js`（附带的两个文件已写好骨架）。
3. **后端**：照第 3、4 节实现，字段名、单位、错误码一个不差。
4. **契约变了必须改版本号 + 群里通知**，不许悄悄改字段。

## 1. 通用约定（这些不写清，联调必吵）

| 项 | 约定 |
|---|---|
| 域名 | 开发 `https://dev-api.xxx.com/api`；生产 `https://api.xxx.com/api` |
| 协议 | 全站 HTTPS（小程序硬性要求），域名需备案 |
| 鉴权 | 登录返回 `token`，之后所有请求带 `Authorization: Bearer <token>` |
| token 有效期 | 2 小时，过期返回 `401`；前端收到 401 清 token 并回登录页 |
| 响应体 | 统一 `{ "code": 0, "msg": "ok", "data": {...} }` |
| 成功判定 | `code === 0`（若后端是 RuoYi 体系，也可用 `200`，**两边选一个写死**） |
| 分页入参 | `pageNum`（从 1 开始）、`pageSize`（默认 10，最大 50） |
| 分页出参 | `{ "total": 36, "list": [...] }` |
| 时间格式 | 日期 `yyyy-MM-dd`；时间 `yyyy-MM-dd HH:mm:ss`；时区固定 +08:00 |
| **ID 类型** | **一律字符串**（`"1856..."`）。用 long 雪花 ID 传给 JS 会精度丢失，这条最容易踩 |
| 字段命名 | 一律 lowerCamelCase，禁止下划线、禁止拼音 |
| 空值 | 数组返回 `[]`，对象没有时返回 `null`，**不要返回空字符串冒充** |
| 单位 | 血压 mmHg、血糖 mmol/L、心率 bpm、体重 kg、身高 cm、体温 ℃ —— 后端不许换单位 |
| 文件上传 | 先 `POST /common/upload` 拿 `url`，再把 url 提交到业务接口 |
| 枚举 | 只传英文小写码值（如 `level: "high"`），中文由前端映射，禁止后端直接返回中文枚举 |

### 错误码表

| code | 含义 | 前端动作 |
|---|---|---|
| 0 | 成功 | 正常取 `data` |
| 401 | 未登录 / token 过期 | 清 token，跳登录页 |
| 403 | 无权限（角色不匹配） | toast「无权限访问」 |
| 1001 | 参数校验失败 | toast `msg` |
| 1002 | 验证码错误 / 过期 | toast `msg` |
| 2001 | 业务规则不允许（如重复打卡） | toast `msg` |
| 5000 | 服务端异常 | toast「服务异常，请稍后再试」 |

## 2. 前端现在的状态（改造起点）

- 全部数据来自 `utils/mock.js`（导出 `patient / risk / todayMetrics / trends / alerts / medications / recipes / emr / roles ...`）。
- 页面里是 `const mock = require('../../utils/mock.js')` 直接同步取数。
- **没有任何接口调用**，也没有 `request.js`。

改造方式：页面不再 `require('mock.js')`，改成 `await api.getHomeSummary()`；`USE_MOCK=true` 时 `api` 内部返回 mock 数据，页面代码零改动即可先跑通，后端起好后把开关关掉。

## 3. 接口清单

> 「对应 mock 字段」列 = 后端返回结构请照这个字段名来，前端不用改渲染代码。

### 3.1 认证与角色

| 方法 | 路径 | 说明 | 主要字段 |
|---|---|---|---|
| POST | `/auth/login` | 登录 | 入：`phone`、`password` 或 `code`；出：`token`、`userId`、`role`、`roles[]` |
| POST | `/auth/register` | 注册 | 入：`phone`、`code`、`password`、`realName` |
| POST | `/auth/sms/code` | 发送短信验证码 | 入：`phone`、`scene`（login/register/reset） |
| POST | `/auth/password/forgot` | 重置密码 | 入：`phone`、`code`、`newPassword` |
| GET | `/auth/roles` | 可选角色列表 | 对应 mock `roles` |
| POST | `/auth/role/switch` | 切换角色 | 入：`role`；出：新 `token`（建议） |

### 3.2 患者档案与亲属

| POST | `/patient/family/bind` | 绑定亲属 | 入：`phone`、`relation`、`verifyCode` |
| DELETE | `/patient/family/{id}` | 解绑 | — |

### 3.3 首页聚合

| 方法 | 路径 | 说明 | 对应 mock |

## 4. 三个关键接口的完整样例（后端照着这个写就行）

### 4.1 登 录

**请求**
```http
POST /api/auth/login
Content-Type: application/json

{ "phone": "13800136688", "password": "123456", "role": "patient" }
```

**成功响应**
```json
{
  "code": 0,
  "msg": "ok",
  "data": {

    "userId": "1856230144770013",
    "role": "patient",
    "roles": ["patient", "family"],
```

```json
{ "code": 1001, "msg": "手机号或密码错误", "data": null }
```

## 5. 联调前 checklist（对着打勾）

- [ ] 契约表逐行过完，双方签字/确认
- [ ] `BASE_URL` 两端一致，测试环境可访问（未备案域名小程序真机不通）
- [ ] 后端在「小程序 → 开发设置 → 服务器域名」里加入 request 合法域名
- [ ] 登录能拿到 token，后续接口带 token 能过鉴权
- [ ] 分页返回 `total` + `list`，前端上拉加载正常
- [ ] 所有 ID 是字符串，前端无精度丢失
- [ ] 时间格式统一，前端不再自己拼日期
- [ ] 错误码按表返回，前端 401 能自动跳登录
- [ ] 上传走 `/common/upload`，返回可直接访问的 https 链接
- [ ] 空数据场景（新用户无记录）不报错、页面有兜底文案
