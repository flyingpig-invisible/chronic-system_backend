# 页面 ↔ 接口映射与开发优先级

> 配合 `接口契约-v1.md` 使用。
> 给后端同学：**按 P0 → P1 → P2 的顺序做**，P0 做完就能开始联调，不用等全部完成。

## 一、接口优先级（后端开发顺序）

| 优先级 | 模块 | 接口 | 为什么这个顺序 |
|---|---|---|---|
| **P0** | 认证 | `/auth/login`、`/auth/sms/code`、`/auth/roles` | 没有登录什么都测不了 |
| **P0** | 首页 | `/home/summary` | 主界面，联调第一条链路 |
| **P0** | 监测 | `/monitor/trends`、`/monitor/disease-tabs` | 图表是核心演示点 |
| **P1** | 预警 | `/alert/summary`、`/alert/list`、`/alert/{id}/read` | 依赖监测数据 |
| **P1** | 用药/计划 | `/medication/*`、`/plan/*` | 患者日常主路径 |
| **P1** | 医生问答 | `/chat/send`、`/chat/history`、`/chat/quick-questions` | 演示重点，建议早做 |
| **P2** | 病历/设备 | `/emr/*`、`/device/*` | 可先用静态数据顶 |
| **P2** | 食谱/指导/文章 | `/recipe/*`、`/guide/*`、`/article/*` | 内容型，可后置 |

## 三、`/home/summary` 为什么必须做聚合

首页如果拆成 5 个接口（患者信息 / 风险评分 / 今日指标 / 今日任务 / 快捷入口），小程序冷启动时要发 5 个并发请求：

- 首屏白屏时间翻倍；
- 任一失败就得整页降级，体验很差；
- 后端还要扛 5 倍 QPS。

所以首页固定一个 `GET /home/summary`，一次返回 `patient / risk / todayMetrics / todayTasks / quickActions` 五个字段。

## 四、字段样例去哪看

直接打开 **`样例数据.json`**：按 `METHOD /path` 为 key，每个接口下面就是完整的 `{ code, msg, data }` 响应，字段名和前端渲染完全一致。

后端可以直接：
1. 照着它建表 / 建 DTO；
2. 拿它当单元测试的期望值；
3. 联调时先用它做 mock 转发（`MockMvc` 或网关 mock）。
